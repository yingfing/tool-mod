请先配置好开发环境，确认项目可以正常编译后，再使用 Mojang 官方映射表、Fabric 1.21.11 语法编写一个 Fabric 客户端 Mod。代码完成后，需配置 GitHub Actions 工作流，实现自动构建与发布 Release，最后将全部代码推送到当前 Git 仓库的当前分支。

【一、环境要求】
- Minecraft 版本：1.21.11
- Mod 加载器：Fabric
- 映射表：Mojang 官方映射（officialMojangMappings）
- JDK：21+
- 构建工具：Gradle + Fabric Loom 1.13+
- 依赖：Fabric API
- 环境：纯客户端 Mod，无需服务端逻辑
- 可选兼容：Mod Menu，用于在模组菜单中提供配置或按键设置入口；若不方便集成，至少支持原版“选项 → 控制 → 按键绑定”中修改按键。

【二、核心功能】
1. 当玩家打开任意容器类界面时，例如背包、箱子、熔炉、漏斗、潜影盒等 AbstractContainerScreen 子类界面：
   - 如果鼠标光标悬停在某个物品槽位上；
   - 按下玩家在模组菜单或原版控制设置中配置的快捷键；
   - 则获取该物品的 Minecraft 注册 ID，格式为“命名空间:路径”，例如：
     - minecraft:ice
     - minecraft:diamond_sword
     - modid:custom_item
   - 将该 ID 字符串复制到系统剪贴板。
   - 在聊天栏或物品栏上方显示反馈，例如：已复制: minecraft:ice

2. 如果按下快捷键时：
   - 没有悬停在任何物品上；
   - 或当前界面不是容器界面；
   - 则给出提示，例如：未悬停在任何物品上；
   - 并且不复制任何内容。

3. 按键要求：
   - 默认按键建议为 C；
   - 必须允许玩家自行修改；
   - 最好能在模组菜单中配置；
   - 至少必须出现在原版“选项 → 控制 → 按键绑定”中；
   - 分类名称可使用“物品 ID 复制”或类似名称。

4. 语言文件要求：
   - 提供 zh_cn.json 和 en_us.json；
   - 包含按键名称、分类名称、复制成功提示、无物品提示等翻译键。

【三、模组显示名称】
- 模组显示名称必须为：当前仓库名-当前分支名
- 例如仓库名为 my-mod，当前分支为 feature/copy-id；
- 则模组显示名称可为：my-mod-feature-copy-id
- 如果分支名包含 / 等特殊字符，显示名称可保留或替换为 -；
- 但 mod id 必须规范化为 Minecraft 合法格式，只允许小写字母、数字、下划线、连字符，即 [a-z0-9_-]。

获取仓库名和分支名的方式：
- 仓库名：通过 git rev-parse --show-toplevel 获取根目录名，或从 git remote get-url origin 解析；
- 分支名：通过 git rev-parse --abbrev-ref HEAD 获取；
- 建议在 Gradle 构建时动态读取，并替换 fabric.mod.json 中的 name、id、version 占位符，避免写死。

【四、GitHub Actions 自动构建与发布 Release】
1. 需要在 .github/workflows/ 目录下创建至少一个工作流文件（如 build-and-release.yml），实现：
   - 在 push 到任意分支时自动构建 Mod（运行 ./gradlew build），并上传构建产物（jar 文件）作为 Artifact 供下载。
   - 在推送以 v 开头的 Git Tag 时（如 v1.0.0），自动构建 Mod 并创建 GitHub Release，将 jar 文件作为 Release Asset 附加。

2. 工作流关键配置要求：
   - 使用 actions/checkout@v4 检出代码；
   - 使用 actions/setup-java@v4 配置 JDK 21（distribution: temurin）；
   - 使用 gradle/actions/setup-gradle@v3 启用 Gradle 缓存以加速构建；
   - 构建前执行 chmod +x gradlew 赋予执行权限；
   - 权限需设置 contents: write，以便创建 Release；
   - Release 创建可使用 ncipollo/release-action@v1 或 softprops/action-gh-release@v2；
   - 工作流需设置合理触发条件，避免每次提交都创建 Release。

3. 版本号规范建议：
   - Mod 版本遵循 {mod_version}+{mc_version} 格式，例如 1.0.0+1.21.11；
   - Git Tag 使用 v{mod_version} 格式，例如 v1.0.0；
   - 推 Tag 时自动触发 Release 构建，Release 名称和 Tag 保持一致。

4. 如果当前环境无法运行 Actions（如本地开发环境无 GitHub 权限），：
   - 仍需将工作流文件写好并提交；
   - 明确说明需要用户推送到 GitHub 后手动触发或创建 Tag 来测试；
   - 不要假装 Actions 已运行成功。

【五、技术实现要点】
- 使用 ClientModInitializer 在客户端初始化。
- 使用 KeyBindingHelper.registerKeyBinding() 注册按键。
- 使用 KeyMapping.Category.register() 注册按键分类。
- 使用 ClientTickEvents.END_CLIENT_TICK 监听按键按下。
- 使用 while (keyMapping.consumeClick()) 处理连续点击。
- 判断当前界面是否为 AbstractContainerScreen。
- 遍历 screen.getMenu().slots，根据鼠标坐标、slot.x、slot.y、getGuiLeft()、getGuiTop() 计算悬停槽位。
- 获取物品 ID：
  itemStack.getItem().builtInRegistryHolder().key().location()
  返回 Identifier 后，拼接 getNamespace() + ":" + getPath()。
- 写入剪贴板：
  Minecraft.getInstance().keyboardHandler.setClipboard(idString)
- 聊天栏反馈：
  client.player.displayClientMessage(Component.translatable(...), false)
- 注意 Mojang 映射下 ResourceLocation 已更名为 Identifier，工厂方法为 Identifier.fromNamespaceAndPath()。
- 处理边界情况：空物品、无注册键、GUI 缩放坐标转换、非容器界面等。

【六、交付物】
- 完整 Fabric Mod 项目结构；
- fabric.mod.json 配置（含动态名称/版本占位符）；
- 客户端入口类；
- 语言文件（zh_cn.json 与 en_us.json）；
- Gradle 动态读取仓库名和分支名的实现；
- .github/workflows/ 下完整的 Actions 工作流文件；
- 构建说明与测试步骤；
- 已提交并推送到当前仓库当前分支的 Git 记录；
- 如果推送或 Actions 运行失败，提供手动执行的 Git 命令和排错指引；
- 代码注释清晰，关键逻辑有说明。
